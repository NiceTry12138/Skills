# 源码深度阅读 SKILL

## 核心原则（不可违反）

1. **基于代码**（最高优先级）：禁止通过名称、注释、文件路径推测任何对象的作用。具体要求：
   - **函数 / 方法**：必须打开源码逐行阅读函数体
   - **类 / 结构体**：必须阅读类定义（字段 + 关键方法 + 继承关系），不能只看类名
   - **属性 / 字段**：必须 grep 该字段名，查看至少 1 处写入和 1 处读取的上下文代码
   - **枚举值**：必须 grep 该枚举值，查看实际使用场景，不能仅按字面翻译
   - 注释、命名、文档字符串仅作为**辅助线索**，结论必须来自代码行为
2. **先筛后读**：先 grep 引用判断是否死代码，零引用的不深入
3. **可追溯**：每个关键结论都要能指向具体文件+行号
4. **诚实标注**：不确定的内容用 ⚠️ 显式声明，禁止伪装成确定结论

## 工作流

### Step 1: 准备工作目录
按 `references/workdir-rules.md` 定位项目根并创建工作目录。
**关键**：工作目录必须在项目根正下方，禁止复用子模块下的同名目录。
开始写笔记前，向用户明确告知最终绝对路径。

### Step 2: 范围筛选
对范围内每个函数/类，用 grep/rg 搜索引用：
- 零引用 → 收入"未使用清单"，不深读
- 有引用 → 进入 Step 3

若预估核心符号 > 50 个，暂停并向用户确认收缩范围。

### Step 3: 精读代码

对每个符号执行**强制阅读动作**（不可跳过）：

| 符号类型 | 强制动作 |
|---------|---------|
| 函数 / 方法 | 打开文件，逐行阅读函数体，识别关键步骤与分支 |
| 类 / 结构体 | 阅读类定义（字段清单、关键方法签名、继承/接口关系） |
| 属性 / 字段 | grep 字段名 → 列出所有读写点 → 至少打开 1 处写入和 1 处读取上下文 |
| 枚举 | grep 各枚举值 → 查看实际判断/赋值场景 |

**跳过条件**：仅当该符号在 Step 2 被判定为零引用死代码时，才可不进入精读。

记录内容：位置、实际作用（基于代码逻辑）、关键步骤、调用方、依赖项。

**属性分级**：
- **A 级**（满足任一）：在主循环中读写 / 被 ≥2 函数读写 / 缓存类（Cache/Last/Pending）/ 状态机字段 / 容器字段
- **B 级**：其他

级属性需要详细档案。**写档案前必须先 Read `references/property-doc-template.md`**，严格按其六要素结构填写。
B 级属性虽用简表，但同样需要先查看使用案例再写说明。

### Step 4: 深度解析复杂逻辑
当函数涉及算法、状态机、并发调度、数学/几何计算、多阶段流水线时，需深度解析。
**必须包含数值走查**（代入具体数字算一遍）。
**必须先 Read `references/algorithm-analysis-template.md`**，按其四要素结构产出。

### Step 5: 绘制架构图
在 `<工作目录>/Image/` 下生成 SVG。中文字体规范见 `references/svg-style-guide.md`。

**按需生成**（不强求数量）：
- `architecture.svg` —— 分层图，**必须含上游调用方和下游依赖**，不是目录树
- `call-graph.svg` —— 关键调用关系，箭头标方向
- `sequence-{流程名}.svg` —— 核心流程时序，用泳道区分角色（流程名用英文 kebab-case，如 `sequence-init.svg`、`sequence-data-sync.svg`）

若模块无对应内容（如纯数据类无时序流程），不强求生成对应图。

### Step 6: 产出笔记
**必须先 Read `references/note-template.md`**，按其完整结构产出 `through_{ts}.md`。

**核心要求**：
- 总览段明确写出**上游和下游**
- 分层至少含**外部接入层**和**底层依赖层**两个边界
- 若有主循环/Tick，调度伪代码必须画**分支判断**（不仅是顺序）
- 功能清单用**工程师视角**（数据结构+算法），不用产品视角（"支持 XX"）
- 未使用代码**独立成节**

## 触发边界（按规模自适应）

| 规模 | 产出策略 |
|------|---------|
| 单函数 / 小脚本 (<200 行) | 简化产出：总览 + 精读 + 可选 1 张图 |
| 单类 / 单模块 | 完整产出 |
| 整个项目 | 先产出总览 + 分层 + 模块清单，再向用户确认深入哪些模块 |

## 完成自检

- [ ] 所有**函数**描述基于读过的函数体，无凭函数名推断
- [ ] 所有**类**描述基于读过的类定义（字段+方法+继承），无凭类名推断
- [ ] 所有**属性**（含 B 级）描述基于查看过的使用案例，无凭字段名推断
- [ ] 所有**枚举值**描述基于查看过的实际使用场景，无凭字面翻译
- [ ] A 级属性档案含具体读写位置（文件:行号）
- [ ] 分层结构含外部接入层（上游）和底层依赖层（下游），不是目录树
- [ ] 复杂算法有数值走查
- [ ] 不确定内容用 ⚠️ 标注
- [ ] SVG 中文显示正常（已声明跨平台字体）
- [ ] 笔记和图片都在 `<项目根>/ThroughtWork/throught_{ts}/` 下
- [ ] 功能清单是工程师视角（数据结构+算法），不是产品描述
- [ ] 未使用代码独立成节，未散落在函数清单中
