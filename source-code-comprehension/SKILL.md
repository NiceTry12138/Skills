# 源码深度阅读与框架梳理 SKILL

## 触发场景

当用户的请求涉及以下任一目标时，自动启用本 SKILL：

- 阅读 / 学习 / 理解 / 分析 函数、类、模块、项目的源码
- 梳理代码的框架结构、分层设计、调用关系
- 输出源码笔记、架构文档、时序流程

## 核心工作流

### 第 1 步：确定阅读范围与对话 ID

1. 明确用户要分析的目标：函数 / 类 / 模块 / 整个项目
2. 获取当前 conversation_id（若无法获取，使用当前时间戳 `YYYYMMDD_HHMMSS` 代替）
3. 在项目根目录创建工作目录：
   ```
   ThroughtWork/throught_{对话id}/
   ThroughtWork/throught_{对话id}/Image/
   ```
4. 创建主笔记文件：`ThroughtWork/throught_{对话id}/through_{对话id}.md`

### 第 2 步：使用情况预检（关键，不能跳过）

对于范围内的每一个函数 / 类：

1. **先全局搜索其引用**（使用 grep / ripgrep），判断是否有实际调用方
2. 如果**没有任何引用** → 在笔记中标记为 `⚠️ 未使用（Unused）`，**不再深入阅读其实现**
3. 如果**有引用** → 进入第 3 步详细阅读

> 这一步可以大幅减少无效阅读，必须在深入之前完成。

### 第 3 步：逐项精读源码（严禁猜测）

针对每一个**确实被使用**的函数 / 类，**必须打开实际代码逐行阅读**，禁止依赖以下任何线索做推断：

- ❌ 不允许仅凭函数名 / 类名 / 属性名推断作用
- ❌ 不允许仅凭注释 / docstring 推断作用（注释可能过时或错误）
- ❌ 不允许仅凭文件名 / 目录名推断模块职责

阅读代码后，记录以下内容：

| 字段 | 说明 |
|------|------|
| 名称 | 函数 / 类全限定名 |
| 位置 | 文件路径 + 行号 |
| 实际作用 | **基于代码逻辑**得出的真实功能 |
| 实现原理 | 关键步骤、关键数据结构、关键分支 |
| 调用方 | 谁在调用它 |
| 依赖项 | 它调用了谁 |
| 复杂度标记 | 是否含复杂计算 |

### 第 4 步：复杂计算的深度解析

当函数涉及以下情况之一时，**必须单列一节深入说明**：

- 数学 / 几何 / 数值计算
- 算法（排序、搜索、图、DP、贪心等）
- 状态机 / 协议解析
- 并发 / 锁 / 调度逻辑
- 加密 / 哈希 / 编解码

需详细说明：

1. **算法原理**：使用了什么思想 / 公式 / 定理
2. **计算步骤**：分步骤说明，最好配数值示例
3. **时间 / 空间复杂度**
4. **边界条件与特殊处理**

### 第 5 步：分层与模块归纳

将所有阅读结果归纳为分层结构：

```
项目/模块
├── 第 1 层：xxx 层（如：接入层 / 表现层）
│   ├── 模块 A —— 负责 xxx
│   └── 模块 B —— 负责 xxx
├── 第 2 层：xxx 层（如：业务逻辑层）
│   └── ...
└── 第 N 层：xxx 层（如：基础设施层）
```

### 第 6 步：绘制 SVG 图（中文不乱码）

在 `ThroughtWork/throught_{对话id}/Image/` 目录下生成至少以下三张 SVG 图：

1. **architecture.svg** —— 框架分层 / 模块结构图
2. **call-graph.svg** —— 关键调用关系图
3. **sequence.svg** —— 核心流程时序图（如有多个核心流程，分别生成 `sequence-xxx.svg`）

**SVG 中文不乱码的强制要求**：

```xml
<svg xmlns="http://www.w3.org/2000/svg" ...>
  <style>
    text {
      font-family: "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", "SimHei", sans-serif;
    }
  </style>
  <!-- 所有 text 元素直接写中文，不要使用 &#xxxx; 实体 -->
  <text x="100" y="50">业务逻辑层</text>
</svg>
```

要点：
- 文件**直接以 UTF-8 编码保存**
- 字体声明涵盖 macOS / Windows / Linux 常见中文字体
- 不使用 HTML 实体转义中文，直接写汉字
- 避免使用某些渲染器不支持的 `<foreignObject>` 包裹中文

### 第 7 步：在 markdown 中引用 SVG

使用相对路径引用：

```markdown
![框架结构](./Image/architecture.svg)
![调用关系](./Image/call-graph.svg)
![核心时序](./Image/sequence.svg)
```

### 第 8 步：标注不确定项

凡是阅读后仍**无法 100% 确定**的部分，**必须显式声明**，禁止伪装成确定结论。使用如下格式：

```markdown
> ⚠️ **不确定**：函数 `foo()` 中第 42 行的位运算用途未能完全确定。
> 推测作用：可能用于位标志压缩存储 X 状态。
> 推测依据：调用方 `bar()` 似乎以位掩码方式读取返回值。
> 仍需验证：缺少 X 状态的定义文件。
```
